제안된 Next.js 프로젝트의 아키텍처 구조도를 제공해드리겠습니다:

```
front-end/
├── app/                        # Next.js App Router
│   ├── (auth)/                # 인증 관련 라우트 그룹
│   │   ├── login/
│   │   ├── register/
│   │   ├── forgot-password/
│   │   └── layout.tsx         # 인증 페이지 공통 레이아웃
│   │
│   ├── (main)/                # 메인 서비스 라우트 그룹
│   │   ├── rooms/            
│   │   │   ├── page.tsx      # 객실 목록
│   │   │   └── [id]/         # 동적 라우팅
│   │   │       └── page.tsx  # 객실 상세
│   │   ├── dining/
│   │   ├── membership/
│   │   ├── giftshop/
│   │   └── layout.tsx        # 메인 페이지 공통 레이아웃
│   │
│   ├── api/                   # API 라우트
│   ├── layout.tsx             # 루트 레이아웃
│   └── page.tsx              # 홈페이지
│
├── components/                # 컴포넌트 디렉토리
│   ├── common/               # 공통 컴포넌트
│   │   ├── ui/              # UI 컴포넌트 (버튼, 입력 등)
│   │   ├── layout/          # 레이아웃 컴포넌트
│   │   └── forms/           # 폼 관련 컴포넌트
│   │
│   ├── rooms/               # 객실 관련 컴포넌트
│   │   ├── RoomCard.tsx
│   │   ├── RoomList.tsx
│   │   └── RoomDetail.tsx
│   │
│   ├── dining/              # 다이닝 관련 컴포넌트
│   ├── membership/          # 멤버십 관련 컴포넌트
│   └── giftshop/           # 기프트샵 관련 컴포넌트
│
├── lib/                     # 유틸리티 및 공통 로직
│   ├── api/                # API 통신 관련
│   ├── hooks/              # 커스텀 훅
│   ├── store/              # 상태 관리
│   │   └── slices/        # Redux/Zustand 슬라이스
│   ├── styles/            # 스타일 관련
│   └── utils/             # 유틸리티 함수
│
├── types/                  # TypeScript 타입 정의
│   ├── rooms.ts
│   ├── dining.ts
│   ├── membership.ts
│   └── giftshop.ts
│
├── tests/                  # 테스트 코드
│   ├── unit/              # 단위 테스트
│   └── integration/       # 통합 테스트
│
├── config/                 # 설정 파일
│   ├── constants.ts       # 상수
│   └── api-config.ts      # API 설정
│
├── public/                 # 정적 파일
│   ├── images/
│   └── fonts/
│
└── docs/                   # 문서화
    ├── api/               # API 문서
    └── components/        # 컴포넌트 문서
```

### 주요 특징:

1. **라우트 그룹화**
   - `(auth)`: 인증 관련 페이지
   - `(main)`: 주요 서비스 페이지

2. **도메인 중심 구조**
   - 각 도메인별 컴포넌트 분리
   - 관련 로직의 응집도 향상

3. **공통 컴포넌트 구조화**
   - UI 컴포넌트 재사용성 강화
   - 레이아웃 컴포넌트 체계화

4. **유틸리티 코드 조직화**
   - API 통신 로직 중앙화
   - 상태 관리 구조화

5. **테스트 및 문서화**
   - 체계적인 테스트 구조
   - 컴포넌트 및 API 문서화

이 구조는 다음과 같은 이점을 제공합니다:
- 코드의 명확한 조직화
- 재사용성 향상
- 유지보수 용이성
- 확장성 제공
- 팀 협업 효율성
